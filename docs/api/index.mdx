title: "Use the API"

Connect authorized applications to Complyz through the API. Send requests to `https://api.trycomplyz.com` and use the `/api/v1` path shown for each operation.

## Versioning

Every operation in this reference belongs to major version 1 and starts with `/api/v1`. The old `/api/...` paths are no longer exposed. Update clients and integrations to use the versioned routes. The URI version identifies the API contract, not the OpenAPI document revision.

Complyz will add compatible operations and fields to version 1 without changing existing behavior. Breaking changes will ship in a new major version. Before a version is retired, Complyz will publish its replacement, migration steps and retirement date. Where supported, responses will announce deprecation and retirement through the `Deprecation` and `Sunset` headers. No version 1 operations are currently marked for retirement.

## Authentication

Sign in with `POST /api/v1/auth/login`. The response tells you whether to set up multi-factor authentication or verify a challenge. Send the access token as a bearer token on authenticated requests:

```http
Authorization: Bearer <access-token>
```

Use `POST /api/v1/auth/refresh` to renew a session. Refresh tokens rotate. Store the new token returned by each refresh and stop using the previous one. Never put tokens in URLs, logs or support messages.

## Response format

Successful JSON responses include the result in `data` and request details in `meta`:

```json
{
  "data": {
    "id": "8b7a83f3-6030-4f84-b8e8-139e9dbf3a4a"
  },
  "meta": {
    "timestamp": "2026-10-02T12:00:00Z",
    "requestId": "4491e196-d873-4d84-9f79-8ab17250e500"
  }
}
```

Failed requests return `error` with a stable code, a message and structured details. Use the HTTP status to decide whether to fix the request, renew the session or try again later. Export operations return files instead of the JSON success envelope.

## Pagination

Paginated lists include the current page in `data`. Use the pagination parameters shown for each operation and follow the metadata returned by the API when moving between pages.

## Data security

Use operations only for data you are authorized to view or change. Do not send Organization IDs to try to expand access. Examples in this documentation use fictional IDs.
