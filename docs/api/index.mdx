Use the Comply API to connect authorized applications to your Organization's workspace. The API reference lists every operation, its request fields, and its responses.

<Note>
  `api.trycomply.com` is currently offline. The API reference describes the current API
  contract; live requests require an available deployment. Ask your administrator for your
  deployment's base URL.
</Note>

## Sign in

### Start authentication

Send your account email and password to the full login URL:

```http
POST https://<your-deployment>/api/v1/auth/login
Content-Type: application/json

{
  "email": "you@example.com",
  "password": "<your-password>"
}
```

The response tells you which multi-factor authentication step to complete:

- `MFA_ENROLLMENT_REQUIRED`: set up multi-factor authentication for the account.
- `MFA_REQUIRED`: verify the sign-in challenge.

For first-time setup, start enrollment and confirm the verification code. For an existing setup, verify the sign-in challenge. Successful verification or enrollment confirmation returns an access token and a refresh token. In the **Authentication** sidebar, open `enrollMfa` to start enrollment, `confirmMfa` to confirm it, or `verifyMfa` to verify a sign-in challenge.

<Warning>
  Replace the example credentials with your own. Do not commit credentials or tokens.
</Warning>

### Send an authenticated request

Send the access token in the `Authorization` header. For example, this request returns the summary available to the signed-in user's Organization:

```bash
curl --request GET \
  --url "https://<your-deployment>/api/v1/insights/summary" \
  --header "Authorization: Bearer ${COMPLY_ACCESS_TOKEN}"
```

Replace `COMPLY_ACCESS_TOKEN` with the access token returned after authentication. Keep access and refresh tokens in a secure secret store. Never put them in URLs, logs, source control, or support messages.

### Refresh an access token

When the access token expires, send the current refresh token to:

```http
POST https://<your-deployment>/api/v1/auth/refresh
Content-Type: application/json

{
  "refreshToken": "<your-refresh-token>"
}
```

The response contains a new access token and refresh token. Store both securely and replace the previous refresh token; it cannot be reused.

## Read API responses

Successful JSON responses place the result in `data` and request details in `meta`. This complete example shows an insights summary:

```json
{
  "data": {
    "totalClients": 0,
    "kycCompleteCount": 0,
    "kycCompletenessPercentage": 0,
    "simplifiedRegimeCount": 0,
    "normalRegimeCount": 0,
    "pendingFlagsCount": 0,
    "sanctionsMatchCount": 0,
    "overdueSlaCount": 0,
    "pepReviewDueCount": 0,
    "totalTransactionsCount": 0,
    "retentionExpiringCount": 0
  },
  "meta": {
    "timestamp": "<timestamp>",
    "requestId": "<request-id>"
  }
}
```

Errors include an error code, message, and details. Use the HTTP status and error response to correct the request, renew the session, or decide whether to retry. Some operations return files instead of a JSON response.

## Versioning and access

Append `/api/v1` once to the deployment base URL provided by your administrator. Use that base URL in place of `https://<your-deployment>` in these examples.

The API authorizes access using the signed-in account and its Organization. Use operations only for information you are authorized to view or change. An Organization ID does not grant access to another Organization's data.
