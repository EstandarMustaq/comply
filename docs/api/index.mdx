Use the Complyz API to connect authorized applications to your Organization's workspace. The API reference lists every operation, its request fields, and its responses.

<Note>
  Use `https://api.trycomplyz.com/api/v1`. The API reference shows full request URLs.
</Note>

## Sign in

### Start authentication

Send your account email and password to the full login URL:

```http
POST https://api.trycomplyz.com/api/v1/auth/login
Content-Type: application/json

{
  "email": "you@example.com",
  "password": "<your-password>"
}
```

The response tells you which multi-factor authentication step to complete:

- `MFA_ENROLLMENT_REQUIRED`: set up multi-factor authentication for the account.
- `MFA_REQUIRED`: verify the sign-in challenge.

For first-time setup, start enrollment and confirm the verification code. For an existing setup, verify the sign-in challenge. Successful verification or enrollment confirmation returns an access token and a refresh token. See the matching operations in the [API reference](/api).

<Warning>
  Replace the example credentials with your own. Do not commit credentials or tokens.
</Warning>

### Send an authenticated request

Send the access token in the `Authorization` header. For example, this request returns the summary available to the signed-in user's Organization:

```bash
curl --request GET \
  --url https://api.trycomplyz.com/api/v1/insights/summary \
  --header "Authorization: Bearer ${COMPLYZ_ACCESS_TOKEN}"
```

Replace `COMPLYZ_ACCESS_TOKEN` with the access token returned after authentication. Keep access and refresh tokens in a secure secret store. Never put them in URLs, logs, source control, or support messages.

### Refresh an access token

When the access token expires, send the current refresh token to:

```http
POST https://api.trycomplyz.com/api/v1/auth/refresh
Content-Type: application/json

{
  "refreshToken": "<your-refresh-token>"
}
```

The response contains a new access token and refresh token. Store both securely and replace the previous refresh token; it cannot be reused.

## Read API responses

Successful JSON responses place the result in `data` and request details in `meta`. This complete example shows an insights summary:

```json
{
  "data": {
    "totalClients": 0,
    "kycCompleteCount": 0,
    "kycCompletenessPercentage": 0,
    "simplifiedRegimeCount": 0,
    "normalRegimeCount": 0,
    "pendingFlagsCount": 0,
    "sanctionsMatchCount": 0,
    "overdueSlaCount": 0,
    "pepReviewDueCount": 0,
    "totalTransactionsCount": 0,
    "retentionExpiringCount": 0
  },
  "meta": {
    "timestamp": "<timestamp>",
    "requestId": "<request-id>"
  }
}
```

Errors include an error code, message, and details. Use the HTTP status and error response to correct the request, renew the session, or decide whether to retry. Some operations return files instead of a JSON response.

## Versioning and access

Use the versioned request URL shown in the API reference. Current operations use `https://api.trycomplyz.com/api/v1`; do not omit the version path or add it twice.

The API authorizes access using the signed-in account and its Organization. Use operations only for information you are authorized to view or change. An Organization ID does not grant access to another Organization's data.
